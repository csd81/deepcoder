# Feature — `/init` (bootstrap AGENTS.md from project analysis)

## Context

Deepcoder auto-loads AGENTS.md if present but has no way to bootstrap one. The README and `/understand` both help an agent learn about the repo, but every new project requires hand-writing AGENTS.md from scratch. OpenCode's `/init` scans the project (package.json, tsconfig, src layout, linters, test framework) and writes a starter AGENTS.md — the user edits it rather than starting from zero.

The repo index (`src/index/`), understand cache (`src/context/understand.ts`), and `/understand` command already enumerate and classify files. `/init` reuses that plumbing and formats the results into an AGENTS.md template.

## Model (what `/init` means)

- `/init` scans the workspace root for well-known config files and source-layout signals, then writes `.deepcoder/instructions.md` (preferred over AGENTS.md to avoid overwriting an existing file).
- If any instruction file already exists (AGENTS.md, CLAUDE.md, .deepcoder/instructions.md), `/init` refuses with a message showing the existing path — never overwrite.
- The generated output covers: project type, key commands (from package.json scripts), test framework, linter, TypeScript strictness, source directory layout, and important conventions detected from config files.
- Read-only analysis, single-file write. Deterministic — same project always produces the same AGENTS.md.

## Design

### 1. Pure module `src/cli/initProject.ts` (the testable core)

```ts
export interface ProjectProfile {
  // From file listing
  hasPackageJson: boolean;
  scripts: Record<string, string>;        // from package.json scripts field
  hasTsconfig: boolean;
  tsStrict: boolean | null;              // null = no tsconfig
  hasReadme: boolean;
  hasGitignore: boolean;
  hasDockerfile: boolean;
  testFramework: string | null;          // detected from devDeps: "vitest" | "jest" | "mocha" | "node:test" | "ava" | "tape" | null
  linter: string | null;                 // "eslint" | "oxlint" | "biome" | "prettier" | "ruff" | null
  formatter: string | null;              // "prettier" | "biome" | "dprint" | "ruff" | null
  pkgManager: string | null;             // "npm" | "pnpm" | "yarn" | "bun" | null
  lang: "ts" | "js" | "python" | "go" | "rust" | "other";
  srcDirs: string[];                     // top-level dirs that look like source (contain .ts/.js/.py files)
  topFiles: string[];                    // well-known root files present
  fileCount: number;
}

export function buildStarterMd(profile: ProjectProfile): string;
```

Detection helpers (pure):
- `detectTestFramework(deps: Record<string,string>): string | null` — checks known devDependency names
- `detectLinter(deps, configFiles): string | null`
- `detectPkgManager(lockFiles: string[]): string | null`
- `detectLanguage(srcFiles: string[]): string`

### 2. I/O layer

The `/init` slash handler:
1. Lists tracked files via `git ls-files` (same as `/understand`).
2. Reads key config files: `package.json`, `tsconfig.json`, linter configs.
3. Calls `buildStarterMd(profile)`.
4. Writes to `.deepcoder/instructions.md` (atomic write, respects current config dir).
5. Prints the path + a brief summary.

### 3. Template (`buildStarterMd`)

Output is a compact AGENTS.md:

```markdown
# Project (auto-generated by /init — review and edit)

## Language & runtime
{lang}, Node {detected version}

## Key commands
| npm run ... | what it does |
|---|---|

## Test
Framework: {testFramework}
`npm test`       # {command}
`npm run test:unit`  # {if exists}

## Lint / format
{linter} / {formatter}

## TypeScript
strict: {yes|no|null}

## Source layout
{srcDirs -> bullet list}

## Architecture notes (add your own below)
<!-- TODO: describe entry points, boundaries, conventions -->
```

### 4. Safety guard

- If `.deepcoder/instructions.md` exists → "Project already initialized (.deepcoder/instructions.md). Edit it directly or remove it first."
- If AGENTS.md or CLAUDE.md exists → "Found existing {path}. /init would write .deepcoder/instructions.md — remove the existing file first, or add this content manually."
- Never overwrite any file.
- All file reads go through existing workspace-safe paths.

## Tests (pure seams — RED first)

`test/init-project.test.ts`:

- `detectTestFramework({"vitest": "^1.0.0"})` → `"vitest"`. Empty deps → null.
- `detectTestFramework({"jest": "^29.0.0", "mocha": "^10.0.0"})` → `"jest"` (first match in priority order: vitest > jest > mocha > node:test ...).
- `detectPkgManager(["pnpm-lock.yaml"])` → `"pnpm"`. No lockfile → null.
- `detectLinter({"oxlint": "^0.1.0"}, [])` → `"oxlint"`.
- `detectLanguage(["src/index.ts", "src/util.js"])` → `"ts"` (ts beats js in priority).
- `buildStarterMd` with a full profile produces markdown containing all sections.
- `buildStarterMd` with minimal profile (no scripts, no deps) produces a minimal template with "No commands detected" fallback.

## Verification

1. `npm run typecheck` clean; `npm run test:phase` green with new tests.
2. Manual: run `/init` in deepcoder's own repo → produces `.deepcoder/instructions.md` with the right commands (dev, build, typecheck, test:phase, etc.).
3. Run `/init` again → refuses (file exists).

## Safety

- Read-only analysis through existing workspace-safe paths. Single write to `.deepcoder/instructions.md` — a gitignored, non-sensitive path.
- Never overwrites existing files. Refuses with a clear message if any instruction file exists.
